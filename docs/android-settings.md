# AirPods settings reference and UI direction

## Product boundary

Preserve iOS AirPods settings structure and the semantics of supported features while reproducing Galaxy Buds 4 Manager visual design. A generic One UI interpretation is not the target. Product artwork comes from upstream LibrePods resources or locally authored primitives. Existing battery-efficiency, responsiveness and nonroot constraints still apply.

Keep future redesign changes concentrated in presentation. Reuse upstream state, capabilities and command paths; do not copy the connection engine or duplicate its state to implement a theme. Existing `Styled*` component signatures provide useful integration points. Some screens still access preferences or construct protocol commands: isolate those dependencies where needed instead of spreading One UI branches into transport code. An upstream update can still change UI contracts and require integration; a presentation boundary does not guarantee conflict-free merges.

The catalog below describes the target information structure, not a claim that LibrePods implements every listed feature. Check each action against code and platform support before making it interactive. Keep supported behavior when moving rows; absent screenshot evidence is not permission to remove capabilities for other AirPods models. Feature gaps require explicit implementation scope, not decorative controls that pretend to work.

It does remove the cost (`issue->swap` 3.35 → 2.60 ms, against the no-fade 2.57) but it **breaks fidelity**: over eight configurations `exact_unequal_app` went 113,092 → 201,558 and summed absolute error 230,408 → 410,040. A translucent overlay quantises twice — once when the premultiplied `background.rgb * cover` is stored, once when the compositor blends it over content — where the recorded band quantises once, so the steep ramps land a step off: at 1440×3120-560-dark the band's ±1 population goes from ±2,900 to −58,795/+66,735, with +1 exceeding −1 by 7,940. Premultiplied output is required either way (returning straight `background.rgb` with `cover` as alpha measured 151,578 above threshold at 480-light with `max_channel_delta` 301), so the overlay was reverted and the replay kept. The overlay build is retained as `session-r56` and its straight-alpha variant as `session-r57`; the dither-phase variant that shifted `noise()` by `bandTop` is `session-r58`, which is worse still (4,837 above threshold at 1440-dark against the shipped 2,393) and confirms the overlay's dither sample must stay unshifted.

No code change was warranted, and none was made.

The edges are drawn as two band-sized layers, not as render effects over the whole foreground. An earlier version applied a `RenderEffect` with an offscreen compositing strategy to the whole foreground — and, with two edges, to the whole foreground again — so every scroll frame ran the viewport through a shader twice. Each band now records only its own rows (56dp at the top, the bottom profile's height below) and runs the shader once over that node, so the offscreen buffer is the band's area rather than the viewport's; bounds and pixel coverage were unchanged by this. Measured on an SM-S947N at 120 Hz with a release build (`dumpsys gfxinfo`, five runs of four swipes per side), the edges cost no measurable frame time: replacing the band shader with one that returns a constant colour measured identically. On the attached SM-S931N at 1080x2340 density 480, the recorded-band build measures p50 8 ms / p90 13 ms / p99 14 ms with GPU p50 3 ms / p90 4 ms on the fixture Home, the same figures as the overlay build before it, so moving the band into a render node added no frame cost. The remaining cost is the content draw itself, not the edges.

Both halves of the scaffold's scroll wiring were costly for the same reason: `ScrollState.value` changes on every scroll frame, so reading it in composition recomposed the scaffold and the whole screen body per frame. The boolean the header and the floating actions need is read through `derivedStateOf`, and the backdrop's offset is read in the draw phase, so a drag recomposes neither.

A runtime shader's output is premultiplied. The band shader must scale its RGB by the alpha it returns; returning straight colour instead makes the compositor divide it back by that alpha, which saturates a near-white background to white at the edge while leaving a dark one apparently correct. The two edges were compared against the original in the light theme at 1440×3120 and agree within the 3/255 dither on the band columns.

A `RuntimeShader` reached through a `ShaderBrush` is evaluated in **canvas** coordinates, not in the coordinates of the rectangle being filled: `ShaderBrush.applyTo` installs no local matrix of its own. The top band starts at row 0 so the distinction does not show there, but the bottom band is filled from `height − fadeHeight` down, and without knowing that origin its rows arrive roughly a thousand pixels past its own height, the curve reads them as past the inner edge and the whole band paints as a flat 80% cover instead of a fade. The shader therefore takes the band origin as a `bandTop` uniform and the edge distance is measured from `position.y − bandTop`; the dither still uses the raw `position`, which is what keeps its field aligned with the Manager's. Both bands also fade towards `indicator_background_color` (`wm.b2` → `pw.e.d`), which is one step darker than the page colour in both themes (#F1F1F3 against #F3F3F5, #010101 against #010102); the band shows that step only where it has cover.

The bottom edge reproduces the One UI fading edge instead of a second linear ramp. `ou.g → m3.i.Q` in the One UI 9 build and `dv.h → lw.b.J` in the One UI 8.5 build give the default profile a 70dp total height, an 18dp lower zone and a 0.24 alpha at that zone's upper bound: alpha falls linearly from 1 to 0.24 over the 52dp above the zone, then continues down through the zone to 0 at the edge. The 0.24 is a waypoint rather than a floor — the original does fade the last stretch to nothing, which the measured profile confirms (the vendor's own lowest text row is drawn at 0.12 alpha, half of 0.24).
