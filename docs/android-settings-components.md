# Settings UI component provenance

The standalone [`:settings-ui` library](../android/settings-ui/README.md) contains presentation primitives for LibrePods settings. The product app does not depend on it yet. Product screens, existing `Styled*` adapters, state and commands have not been migrated. Neutral public names describe roles; vendor names appear here to identify evidence.

## Integration and verification boundary

The kit covers the presentation categories used by LibrePods settings. It does not implement unrelated manager features or migrate product screens. The existing app stays the source of truth for feature support, AirPods model conditions, state and command encoding. Future integration should adapt its existing `Styled*` facades and supply existing callbacks rather than duplicate the engine.

Library builds and host tests check compilation and scroll-reporter ownership. The isolated instrumentation tests exercise focus/editing, disabled/single toggle actions, confirmation versus dismissal, and upward-increasing vertical gain. An emulator supplies Compose/platform interaction evidence, not Samsung glyphs, pixel parity, Bluetooth operation, battery consumption or performance measurements. The debug gallery documents usage and includes light/dark/large-type previews; its presence is not proof that every preview or visual state was measured.
